# Phase 70 New-Word Limits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The learner's daily new-word cap and new words per session become settings, and a session the cap held words back from says so once.

**Architecture:** Two nullable `users` columns feed the picker through a `NewWordLimits` value (pure domain); the picker runs a second, uncapped time to count the words the cap held back, which the stock records on the session row; `GET /api/sessions/{id}` reports it while it is news; the app shows a sheet on the session screen and gains a settings screen.

**Tech Stack:** Hono + zod-openapi, drizzle/Postgres, Jest; Expo Router React Native; Playwright.

**Spec:** `docs/superpowers/specs/2026-10-22-lang-tutor-phase-70-new-word-limits-design.md`

## Global Constraints

- Defaults unchanged: day cap 15 (`DAY_NEW_CAP`), per session automatic (null) = today's rule; `day.test.ts` passes untouched in its assertions.
- Per session is null, 1 or 2; the ceiling stays `NEW_PER_SESSION` (2). Day cap on the wire: whole number 1–100; screen chips 5, 10, 15, 20, 30, 50.
- A saved day cap equal to `DAY_NEW_CAP` is stored as null.
- Additive wire changes only; `API_LEVEL` unchanged (ADR 0012). Every endpoint through `createRoute` with schemas in `packages/core` (ADR 0003).
- Hebrew copy verbatim from spec D6/D7; strings in `apps/mobile/src/strings.ts`.
- Migration `0050_new_word_limits`, generated by `npm run db:generate -w apps/server -- --name new_word_limits`; new columns carry a default or are nullable.

## Review Focus

- A cap lowered below today's first meetings: room is 0, never negative; no new word, held counted (Task 1 test).
- Per session 2 with one new word waiting: one new word, the rest reviews (Task 1 test).
- A target session in owed mode records 0 held, whatever the cap (Task 1 test).
- A seed session, or one chosen before this phase (`chosen_on` null, `day_new_cap` null), reports no `held_new_words` (Task 3 test).
- `PUT /api/me/new-words` with `per_session` 0 or 3, or `day_cap` 0 or 101: 400 `{ error: 'invalid request' }` (Task 2 test).
