# Typed cards' help row Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a typed card with help, the answer bar has two rows from the start: help's row (עזרה beside a dashed box holding help's reading) above the answer row (בדיקה beside the input). The layer drawn behind the input goes.

**Architecture:** Help's rules and the session's help state are unchanged. `TypedAnswerView` draws the same three parts the layer drew (typed text, marked part, grey given letters) as ordinary text in a dashed box, computed by a new pure `helpReading` in `typedHelp.ts`. `HelpButton` takes a `style`, so the row can give it בדיקה's width.

**Tech Stack:** Expo SDK 57, React Native 0.86, Jest (jest-expo, pure logic only), Playwright e2e on web.

**Spec:** `docs/superpowers/specs/2026-10-21-lang-tutor-help-row-design.md`

## Global Constraints

- Touch only `apps/mobile/src/typedHelp.ts` and its test, `apps/mobile/src/components/TypedAnswerView.tsx`, `apps/mobile/src/components/HelpButton.tsx`, and `e2e/tests/help.spec.ts` and `e2e/tests/sentence-cards.spec.ts`. No server, core, string or API-level change.
- Keep every testID in the spec's D7. Add `typed-help-row` (the dashed box) and `typed-bar` (the bar).
- No physical `left`/`right` or `textAlign` on a `Text` (phase 63 B8). Pad by start and end.
- Copy is the existing strings: `strings.help`, `strings.typedCheck`, `strings.checking`, `strings.tryAgain`, `strings.typedPlaceholder`.

## Review Focus

1. **An Italian reading's side on Android.** It must start at its box's left. The container sets `direction` and the `Text` sets `writingDirection`, and only the phone shows the result (Left for Victor).
2. **A long wrong typing** marked by help must show whole, wrapping if it must, with עזרה still in view. Task 2 adds an e2e step.
3. **בודקים… and נסו שוב** must fit the fixed button width without wrapping or truncating. Check in the Task 2 e2e run's screenshot of the checking state, or by eye on web.
4. **The 390 × 360 viewport check:** the question, the input and בדיקה must all show unscrolled. It already exists, and the two rows must not make the bar taller.
5. **A card turned typed with letters already given** must show them in the reading before any press. speaking.spec.ts already checks this.

### Task 1: The help row

**Files:**
- Modify: `apps/mobile/src/typedHelp.ts` (add `helpReading`)
- Test: `apps/mobile/src/typedHelp.test.ts`
- Modify: `apps/mobile/src/components/HelpButton.tsx` (optional `style` prop)
- Modify: `apps/mobile/src/components/TypedAnswerView.tsx`

**Interfaces:**
- Produces: `export function helpReading(typed: string, markFrom: number | null, ghost: string): { typed: string; marked: string; ghost: string } | null`. It returns null when `markFrom` is null and `ghost` is `''`. Otherwise `typed` is the typing before `markFrom` (all of it when null), `marked` is the typing from `markFrom` (`''` when null), and `ghost` is passed through.
- Produces: `HelpButton` props gain `style?: StyleProp<ViewStyle>`, applied last on the `Pressable`.

- [ ] **Step 1: Write the failing tests** in `typedHelp.test.ts`, `describe('helpReading')`:
  - `helpReading('fred', null, '')` → `null`
  - `helpReading('freddghgfhhhff', 5, '')` → `{ typed: 'fredd', marked: 'ghgfhhhff', ghost: '' }`
  - `helpReading('fred', null, 'd…')` → `{ typed: 'fred', marked: '', ghost: 'd…' }`
  - `helpReading('', null, 'f…')` → `{ typed: '', marked: '', ghost: 'f…' }`
- [ ] **Step 2: Run them to see them fail:** `npx jest src/typedHelp.test.ts` in `apps/mobile`. Expect: `helpReading` is not a function.
- [ ] **Step 3: Implement `helpReading`** as described in Interfaces.
- [ ] **Step 4: Run them to see them pass:** same command, all green.
- [ ] **Step 5: `HelpButton`** gets the `style` prop.
- [ ] **Step 6: `TypedAnswerView`.**
  - Remove the layer `Text`, the `overflow` state, and the `layer`, `hidden` and `under` styles. Remove `paddingStart` from `box`, and the `HelpButton` from inside the box.
  - The placeholder is always `strings.typedPlaceholder`.
  - The `reading = helpReading(text, markFrom, ghost)` uses today's `markFrom` and `ghost`.
  - The bar (`testID="typed-bar"`) holds: the note as today; then, when `helps`, help's row; then the answer row.
  - **Help's row:** a row with `gap: spacing.sm`, `alignItems: 'stretch'`. First child: `HelpButton` (`typed-help`, today's `disabled` and `onPress`) styled `{ width: SIDE_BUTTON, justifyContent: 'center' }`. Second: the dashed box `View` (`typed-help-row`): `flex: 1`, `borderWidth: 1.5`, `borderStyle: 'dashed'`, `borderColor: colors.border`, `borderRadius: radii.md`, `paddingHorizontal: spacing.md`, `paddingVertical: spacing.sm`, `minHeight: 48`, `justifyContent: 'center'`, `direction` set to the answer's direction. When `reading` is not null, the box holds a `Text` (`typed-hint`, `fontSizes.md`/`lineHeights.md`, `colors.text`, `writingDirection: direction`). The `Text` holds `reading.typed`, then a nested `Text` `typed-marks` with today's `marked` style when `marked !== ''`, then a nested `Text` `typed-ghost` with today's `ghost` style when `ghost !== ''`.
  - **The answer row:** a row with `gap: spacing.sm`. Its `alignItems` is `'flex-end'` on a sentence translation and `'stretch'` otherwise. First child: the button (today's `testID`, label, `disabled` and `onPress`), styled `answerStyles.check` without `alignSelf: 'stretch'`, plus `{ width: SIDE_BUTTON, justifyContent: 'center' }`. Second: the `box`, with `flex: 1`.
  - `const SIDE_BUTTON = 104;` must fit בודקים… at `fontSizes.md` bold.
  - The locked box in the card is unchanged: no help, full width.
