# Phase 43 — A session is always ready: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (Victor: "go till PR", inline). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every enrollment with saved words keeps one unstarted session in stock, refilled when a
session starts, so the learner never waits for one.

**Architecture:** `sessions.started_at` and two partial unique indexes let a started session and a
stock coexist. A `stock-session` job (pg-boss, `stately`, one per enrollment) runs phase 19's list
branch of create, now `stockNext`, with the started session's glosses treated as answered today.
Start (a new route, or the first answer), completion, skip and saves enqueue it. The app sends
start with the device's capabilities and makes a missing stock itself instead of offering a button.

**Tech Stack:** TypeScript, Drizzle, pg-boss 12, Hono + zod-openapi, Jest, Expo Router, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-lang-tutor-phase-43-always-ready-session-design.md`

## Global Constraints

- `API_LEVEL` does not change (R6); no request field becomes required.
- Migration `0031`, generated by `npx drizzle-kit generate --name always_ready_session` from
  `apps/server`, then hand-edited for the backfill (`DEFAULT false` added then dropped).
- Skip is untouched for everyone.
- Every enqueue goes through `repo/jobs.ts`; every handler is one service call in `worker.ts`
  (ADR 0007).
- Lanes are full in this run: unit, typecheck, `lint:arch` and single integration files under a
  throwaway `TEST_DB_PREFIX` run locally; the full integration and e2e suites are proven in CI.

## Review Focus

1. Answering the stock while another session is started must be a 409 `session_open`, never a
   500 or two started sessions: pinned in Task 1 (index) and Task 3 (service maps it).
2. The home auto-create must not loop when create fails (`no_saved_words` with saved words but no
   askable rendering): pinned in Task 6's helper test.
3. A stock built while a session is started must not repeat its words when the list has others,
   and must still be full when it has not: Task 2.
4. A trigger arriving while a stock job runs must not be lost: the `stately` policy, Task 4's
   queue-definition test.
5. Start on a `preparing` session must be refused (no questions yet), and start twice is a no-op:
   Task 3.
